# FarmOS API Endpoints

Base URL: configured by server host/port. Default docs at `/docs`, OpenAPI at `/openapi.json`.

## Final AI Response

The end-user facing AI text is always the `AIexplanation` field in the API response. It is returned by the endpoint itself and is already localized to the requested language.

Sources:
- `/analyze/leaf`: `AIexplanation` in the JSON response.
- `/groundwater/analyze`: `AIexplanation` in the JSON response.

The text is generated by `openai/gpt-oss-120b` via the Groq API. Set `GROQ_API_KEY=...` in a `.env` file next to `main.py` (git-ignored) or as an environment variable.

If the Groq call fails (missing key, network error, rate limit), both endpoints return a fallback explanation (rule-based text) in the same `AIexplanation` field so the API response never breaks, and set `fallback_used: true`.

## Leaf Analysis

Router prefix: `/analyze`

### POST /analyze/leaf

**Purpose**: Upload a leaf image and optional environmental/location inputs. Returns a simplified leaf health analysis plus AI explanation.

**Content-Type**: `multipart/form-data`

**Form fields**
- `leaf_image` (file, required): JPEG/PNG/WEBP. Max size 15 MB.
- `wind_force_ms` (float, optional): Wind speed in m/s. Range: 0.0–200.0.
- `humidity_pct` (float, optional): Relative humidity %. Range: 0.0–100.0.
- `temperature_c` (float, optional): Air temperature in °C. Range: -50.0–70.0.
- `sunlight_lux` (float, optional): Sunlight illuminance in lux. Range: 0.0–150000.0.
- `users_question` (string, optional): Farmer question to answer in the AI explanation.
- `selected_language` (string, optional): Language for AI response. Options mentioned in code: English, Hindi, Marathi. Default: English.
- `latitude` (float, optional): Farm latitude. If provided with longitude, groundwater data is included in AI analysis.
- `longitude` (float, optional): Farm longitude. If provided with latitude, groundwater data is included in AI analysis.

**Response (200, application/json)**
`LeafAnalysisResponse`
```json
{
  "image_width": 0,
  "image_height": 0,
  "total_pixels": 0,
  "leaf_pixel_count": 0,
  "green_pixel_count": 0,
  "green_ratio": 0.0,
  "yellow_ratio": 0.0,
  "brown_ratio": 0.0,
  "is_healthy": true,
  "health_label": "healthy",
  "health_status": "HEALTHY",
  "health_score": 0.0,
  "severity": 1,
  "detected_issues": ["..."],
  "recommendation": "...",
  "regions": {
    "L": {"hex_color": "#5A7A3B", "green_ratio": 0.0, "yellow_ratio": 0.0, "brown_ratio": 0.0, "coverage_ratio": 0.0},
    "R": {}, "T": {}, "D": {}, "C": {}
  },
  "lrtdc_vector": "(L,#5A7A3B)(R,#...)(T,#...)(D,#...)(C,#...)",
  "health_summary": {"health_score": 0.0, "health_label": "healthy", "greenness_pct": 0.0,
                     "yellowing_pct": 0.0, "necrosis_pct": 0.0, "recommendation": "..."},
  "wind_force_ms": 0.0,
  "humidity_pct": 0.0,
  "temperature_c": 0.0,
  "sunlight_lux": 0.0,
  "latitude": 0.0,
  "longitude": 0.0,
  "users_question": "...",
  "selected_language": "English",
  "AIexplanation": "...",
  "fallback_used": false
}
```

**Notes on response fields**
- The leaf is separated from the background first; `green_ratio`, `yellow_ratio` and `brown_ratio` are fractions (0–1) of the **leaf**, not the whole photo (green = healthy, yellow = chlorosis, brown = dead tissue).
- `is_healthy` is false when yellow + brown ≥ 7% of the leaf, or there is a distinct brown lesion (≥ 2.5% brown with one patch ≥ 1% of the leaf or ≥ 10 spots).
- `health_score` is 0–100 (≥ 80 healthy, 50–80 needs attention, < 50 critical); `severity` is 1–5.
- `detected_issues` lists findings such as "large brown dead patch (~19% of the leaf)"; `regions` breaks the leaf into L/R/T/D/C.
- `health_summary` repeats the main values grouped, for app versions that read it.
- `health_label` is one of `healthy`, `not_healthy`.
- Works best with one leaf filling most of the frame; whole-plant or very cluttered photos are less reliable.
- `AIexplanation` comes from Groq; it falls back to the rule-based recommendation if the Groq call fails.
- `fallback_used` is true when `AIexplanation` is the rule-based fallback rather than AI text.

**Error responses**
- 400: Bad image or invalid parameters.
- 413: File too large.
- 422: Validation error.
- 500: Internal processing error.

Error schema (as declared):
```json
{
  "detail": "...",
  "code": "..."
}
```

## Groundwater Analysis

Router prefix: `/groundwater`

Groundwater stats and maps are cached in memory per ~5 km map tile, so repeat requests for the same farm (including `/analyze/leaf` with coordinates) skip the satellite download. One `/groundwater/analyze` call also caches the map for the `map_image_url` it returns. The cache resets when the server restarts.

### POST /groundwater/analyze

**Purpose**: Returns groundwater potential stats and an AI explanation for the provided coordinates.

**Content-Type**: `multipart/form-data`

**Form fields**
- `latitude` (float, required): Range -90 to 90.
- `longitude` (float, required): Range -180 to 180.
- `selected_language` (string, optional): English, Hindi, Marathi. Default: English.

**Response (200, application/json)**
```json
{
  "lat": 0.0,
  "lon": 0.0,
  "groundwater_potential": {
    "very_high_pct": 0.0,
    "high_pct": 0.0,
    "medium_pct": 0.0,
    "low_pct": 0.0,
    "very_low_pct": 0.0
  },
  "AIexplanation": "...",
  "selected_language": "English",
  "ai_available": true,
  "fallback_used": false,
  "map_image_url": "/groundwater/map?latitude=...&longitude=..."
}
```

**Error responses**
- 500: Groundwater analysis failed.

---

### GET /groundwater/map

**Purpose**: Returns a JPEG satellite map (~0.5 MB) for the provided coordinates.

**Query parameters**
- `latitude` (float, required): Range -90 to 90.
- `longitude` (float, required): Range -180 to 180.

**Response (200, image/jpeg)**
- JPEG bytes.
- Response headers include:
  - `Content-Disposition: inline; filename="gw_map_<lat>_<lon>.jpg"`
  - `X-Latitude: <lat>`
  - `X-Longitude: <lon>`

**Error responses**
- 500: Map generation failed.
